# Migrate from Pytincture 0.10 to 1.0

The 1.0 line formalizes APIs and removes accidental dependency coupling. Use a
release candidate in staging before changing production.

## Installation extras

The base wheel no longer installs test tools, `pyodide-py`, Authlib, OneLogin,
Upstash, FastMCP, Argon2, or bcrypt. Install what the deployment enables:

```bash
pip install "pytincture[password,oauth,saml,redis,mcp]"
```

Contributors use `pip install ".[dev]"`. A startup/use error naming an extra
means the feature is enabled without its dependency group.

## Application factory and configuration

Prefer an importable ASGI application:

```python
from pytincture import PytinctureConfig, create_app

config = PytinctureConfig.from_env()
app = create_app(config)
```

Direct construction is isolated and does not read the environment.
`from_env()` applies explicit overrides, then environment values, then typed
defaults. Invalid modules paths, auth secrets/providers, Redis settings, CORS,
cookie policy, limits, replay-token sizes, proxy behavior, and log levels fail
at startup. `launch_service()` remains supported.

Proxy-header trust now defaults off for both the factory and compatibility
launcher. Deployments behind a trusted reverse proxy must explicitly set
`PYTINCTURE_TRUST_PROXY_HEADERS=true`. Authentication-enabled production
deployments now fail startup unless `PYTINCTURE_ALLOWED_HOSTS` contains exact
hostnames and `PYTINCTURE_CANONICAL_ORIGIN` is one HTTPS origin. Local HTTP
authentication tests can opt into request-derived origins with
`PYTINCTURE_ALLOW_DEVELOPMENT_AUTH_ORIGIN=true` plus
`AUTH_SESSION_HTTPS_ONLY=false`; the supported launcher restricts this mode to
loopback.

## Runtime behavior

- The unscoped `/classcall/{file}/{class}/{method}` compatibility route has
  been removed. Manual BFF clients must call
  `/{application}/classcall/{file}/{class}/{method}`. The application must be a
  real entrypoint and the BFF module must belong to its browser dependency
  graph. Generated clients already emit the scoped form. In services with all
  authentication providers disabled, `@backend_for_frontend` remains the
  public export decision; no additional method allowlist is required.
- Packaged execution failures no longer silently fall back to inline code.
  Handle `PytinctureLifecycleError` and lifecycle events.
- `/healthz` and `/readyz` are the supported process/orchestration probes.
- Security logs are JSON and carry validated/generated request IDs.
- BFF calls and streams have time/byte limits and deterministic cleanup.
- Signed browser sessions and one-time handshake capsules remain stateless and
  work across multiple workers without Redis or sticky sessions. Optional
  remote revocation storage is an additional deployment feature, not a runtime
  requirement.
- Authenticated sessions now have an absolute lifetime in addition to their
  idle lifetime. Configure `AUTH_SESSION_ABSOLUTE_MAX_AGE_SECONDS` if the
  24-hour default is not appropriate. Previous signing keys must meet the same
  strength policy as the current key.
- Login forms are browser-bound and logout is now a CSRF-protected `POST`.
- Microsoft OAuth requires `MICROSOFT_TENANT_ID`; the `common` tenant endpoint
  is no longer accepted. Google login requires the provider's verified-email
  claim.
- Framework static files are served from an explicit manifest, app responses
  carry baseline browser security headers, and generated browser bundles plus
  the vendored Pyodide SBOM/checksums are verified by CI.
- Direct `/{application}/appcode/{asset}` URLs now require a real application
  entrypoint and an explicit browser/public/favicon/widget declaration. If an
  app previously relied only on a filename extension, add the asset to
  `PYTINCTURE_BROWSER_FILES` or `PYTINCTURE_PUBLIC_ASSET_PATHS`. These URLs are
  still unauthenticated. Use the application-keyed JSON public-asset form for
  multi-app isolation; legacy list/CSV values intentionally remain shared.
- MCP is not mounted unless `ENABLE_MCP=true` and requires the `mcp` extra.
  MCP now requires a JWT verifier, exact Host/Origin lists, and `MCP_TOOLS`
  entries that bind unique tool names and scopes to exact BFF exports. The old
  `MCP_EXPOSED_OPERATIONS` generic FastAPI conversion has been removed.

Browser package loading now requires exact `name==version` pins or
SHA-256-locked wheel URLs. Automatic transitive installs are disabled; list
each browser dependency explicitly. Widgetsets that contain JavaScript or CSS
ship a hashed `pytincture-assets.json` instead of relying on recursive
site-packages scanning. Existing `dhxpyt==0.9.16` applications use the bundled
compatibility lock. See [widgetset packaging](../widgetset-packaging.md).
Backend wheel routes now expose only that declared version and the explicit
`PYTINCTURE_DEV_WHEEL_VERSION` fallback (`99.99.99` by default), rather than
every root-level version sharing the distribution name.

## Public versus internal APIs

Only names in [`contracts/public-api-v1.json`](../../contracts/public-api-v1.json)
or an explicit versioned contract are stable. Do not import registry globals,
route functions, middleware internals, generated-stub helpers, or underscore
names. Replace direct `backend.app.app` deployment with `create_app()`.

## Staging checklist

Build from a lockfile, inspect the release artifacts, run the cross-browser
application, verify all auth providers, test proxy HTTPS/callback URLs, force a
stream timeout/disconnect, restart workers, test rollback, and retain the old
session key in `AUTH_SESSION_PREVIOUS_SECRET_KEYS` during rollout.
