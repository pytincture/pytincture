# Migrate from Pytincture 0.10 to 1.0

The 1.0 line formalizes APIs and removes accidental dependency coupling. Use a
release candidate in staging before changing production.

## Installation extras

The base wheel no longer installs test tools, `pyodide-py`, Authlib, OneLogin,
Upstash, FastMCP, Argon2, or bcrypt. Install what the deployment enables:

```bash
pip install "pytincture[password,oauth,saml,redis,mcp]"
```

Contributors use `pip install ".[dev]"`. A startup/use error naming an extra
means the feature is enabled without its dependency group.

## Application factory and configuration

Prefer an importable ASGI application:

```python
from pytincture import PytinctureConfig, create_app

config = PytinctureConfig.from_env()
app = create_app(config)
```

Direct construction is isolated and does not read the environment.
`from_env()` applies explicit overrides, then environment values, then typed
defaults. Invalid modules paths, auth secrets/providers, Redis settings, CORS,
cookie policy, limits, replay-token sizes, proxy behavior, and log levels fail
at startup. `launch_service()` remains supported.

Proxy-header trust now defaults off for both the factory and compatibility
launcher. Deployments behind a trusted reverse proxy must explicitly set
`PYTINCTURE_TRUST_PROXY_HEADERS=true`. Authentication-enabled production
deployments now fail startup unless `PYTINCTURE_ALLOWED_HOSTS` contains exact
hostnames and `PYTINCTURE_CANONICAL_ORIGIN` is one HTTPS origin. Local HTTP
authentication tests can opt into request-derived origins with
`PYTINCTURE_ALLOW_DEVELOPMENT_AUTH_ORIGIN=true` plus
`AUTH_SESSION_HTTPS_ONLY=false`; the supported launcher restricts this mode to
loopback.

## Runtime behavior

- Hosted custom widgetsets now load the exact backend wheel before any public
  package-index source. Preserve that wheel in `MODULES_PATH` during deployment.
  If a service intentionally installs a custom widget from PyPI, add its exact
  `name==version` to `PYTINCTURE_WIDGET_PUBLIC_INDEX_ALLOWLIST`. Standalone
  applications still make their own explicit source decision. The built-in
  `dhxpyt==0.9.18` fallback remains protected by its complete-wheel SHA-256.
- `1.0.0rc4` rejects encrypted SAML assertions before signature processing.
  Configure the IdP to send signed, unencrypted assertions. Signed SAML
  responses and signed assertions remain supported under the documented
  correlation and algorithm requirements.
- The optional `isolated-process` BFF executor now accepts and returns only
  bounded JSON-compatible values. Custom objects that previously crossed that
  boundary through Python pickle must be converted to dictionaries, lists,
  strings, numbers, booleans, or `None`. The default thread/async executor is
  unchanged.
- Standalone applications using an external Pyodide CDN must provide trusted
  script integrity and explicitly set `allowUnverifiedExternalPyodide: true`.
  Self-hosted exported runtime assets remain the production default. This
  explicit opt-in is intentionally incompatible with silently executing an
  unverified external runtime.
- dhxpyt chat history is no longer implicitly persisted as plaintext. Set an
  explicit `storageKey` to retain the existing persistence behavior. Assistant
  text and ordinary widget values are rendered as inert content; applications
  that intentionally relied on executable HTML in those values must move that
  content to an explicitly trusted, isolated artifact preview.
- Existing generated synchronous BFF methods remain available through 1.x.
  Async companions are additive, and transport/replay refill now run with
  bounded waits and single-flight coordination. No Redis, sticky session, or
  server-side browser session is required.
- The unscoped `/classcall/{file}/{class}/{method}` compatibility route has
  been removed. Manual BFF clients must call
  `/{application}/classcall/{file}/{class}/{method}`. The application must be a
  real entrypoint and the BFF module must belong to its browser dependency
  graph. Generated clients already emit the scoped form. In services with all
  authentication providers disabled, `@backend_for_frontend` remains the
  public export decision; no additional method allowlist is required.
- Manual BFF clients must send one JSON object containing both `args` and
  `kwargs`, for example `{"args": [], "kwargs": {"value": 1}}`. Remove
  `JSON.stringify(json.dumps(...))`, JSON-string bodies, bare kwargs objects,
  and structured `{name, type, value}` positional wrappers. Generated 1.0
  clients already encode the canonical object once. GET exports must be
  parameterless, read-only, repeatable, and bodyless.
- BFF request uploads now have a separate 10-second default ingress limit and
  complete before execution admission. Raise
  `BFF_REQUEST_INGRESS_TIMEOUT_SECONDS` for intentionally slow clients; this
  does not shorten `BFF_CALL_TIMEOUT_SECONDS` or long-running backend work.
- Streaming BFF writes now have a separate 30-second per-frame blocked-write
  limit. Moving chunks reset `BFF_STREAM_WRITE_TIMEOUT_SECONDS`; generators,
  async generators, `yield`, and the total stream duration remain supported.
- Generated BFF clients now raise `PytinctureBFFError` for non-2xx responses
  instead of attempting to decode error bodies as successful values. Existing
  401 login redirects remain. Policy hooks that explicitly return `False` now
  deny the call; use `True` or `None` to allow it.
- Packaged execution failures no longer silently fall back to inline code.
  Handle `PytinctureLifecycleError` and lifecycle events.
- `/healthz` and `/readyz` are the supported process/orchestration probes.
- Security logs are JSON and carry validated/generated request IDs.
- BFF calls and streams have time/byte limits and deterministic cleanup.
- Ordinary BFF responses now default to a 10 MiB serialized limit plus bounded
  depth/items. Raise `BFF_RESULT_MAX_BYTES` only for an intentional larger API.
  Trusted thread/async execution remains the default; optional
  `BFF_EXECUTION_MODE=isolated-process` is available for non-streaming code that
  needs a killable process boundary.
- Signed browser sessions and one-time handshake capsules remain stateless and
  work across multiple workers without Redis or sticky sessions. Optional
  remote revocation storage is an additional deployment feature, not a runtime
  requirement.
- Authenticated sessions now have an absolute lifetime in addition to their
  idle lifetime. Configure `AUTH_SESSION_ABSOLUTE_MAX_AGE_SECONDS` if the
  24-hour default is not appropriate. Previous signing keys must meet the same
  strength policy as the current key.
- Login forms are browser-bound and logout is now a CSRF-protected `POST`.
- Microsoft OAuth requires `MICROSOFT_TENANT_ID`; the `common` tenant endpoint
  is no longer accepted. Google login requires the provider's verified-email
  claim.
- OAuth initiation and callback work is now bounded by configurable `OAUTH_*`
  rates, provider-exchange concurrency, and HTTP/overall deadlines. Routes for
  missing application entrypoints return `404` before contacting the provider.
  The defaults are generous, process-local, stateless, and require no Redis.
- Framework static files are served from an explicit manifest, app responses
  carry baseline browser security headers, and generated browser bundles plus
  the vendored Pyodide SBOM/checksums are verified by CI.
- Direct `/{application}/appcode/{asset}` URLs now require a real application
  entrypoint and an explicit browser/public/favicon/widget declaration. If an
  app previously relied only on a filename extension, add the asset to
  `PYTINCTURE_BROWSER_FILES` or `PYTINCTURE_PUBLIC_ASSET_PATHS`. These URLs are
  still unauthenticated. Use the application-keyed JSON public-asset form for
  multi-app isolation; legacy list/CSV values intentionally remain shared.
  Direct asset delivery is now bounded and its authorization is cached by
  secure entrypoint identity. The default per-file ceiling is 64 MiB; raise
  `PYTINCTURE_PUBLIC_ASSET_MAX_BYTES` for an existing larger asset or move large
  media to object storage. Slow clients are disconnected without affecting
  normally moving files.
- MCP is not mounted unless `ENABLE_MCP=true` and requires the `mcp` extra.
  MCP now requires a JWT verifier, exact Host/Origin lists, and `MCP_TOOLS`
  entries that bind unique tool names and scopes to exact BFF exports. The old
  `MCP_EXPOSED_OPERATIONS` generic FastAPI conversion has been removed. MCP
  JWTs must also contain finite `iat` and `exp` claims and stay within the
  configured clock-skew, maximum-age, and maximum-lifetime policy. Existing
  issuers can temporarily set `MCP_ALLOW_LEGACY_TIMELESS_TOKENS=true` while
  migrating; the setting is intentionally disabled by default.

Browser package loading now requires exact `name==version` pins or
SHA-256-locked wheel URLs. Automatic transitive installs are disabled; list
each browser dependency explicitly. Widgetsets that contain JavaScript or CSS
ship a hashed `pytincture-assets.json` instead of relying on recursive
site-packages scanning. Existing `dhxpyt==0.9.18` applications use the bundled
compatibility lock. See [widgetset packaging](../widgetset-packaging.md).
Backend wheel routes now expose only that declared version and the explicit
`PYTINCTURE_DEV_WHEEL_VERSION` fallback (`99.99.99` by default), rather than
every root-level version sharing the distribution name.

Generated synchronous BFF methods remain callable in 1.x, so existing browser
code does not need an immediate rewrite. They now emit a normally hidden
`DeprecationWarning` and each receives an additive async companion when that
name is not already exported: replace
`result = service.save(...)` with `result = await service.save_async(...)` when
the surrounding browser function can be async. The companion uses bounded,
non-blocking fetch and single-flight replay-token refill. Declaring the backend
method itself as `async def` continues to generate the original async method
name. No Redis, in-memory server session, or sticky worker is introduced.

## Public versus internal APIs

Only names in [`contracts/public-api-v1.json`](../../contracts/public-api-v1.json)
or an explicit versioned contract are stable. Do not import registry globals,
route functions, middleware internals, generated-stub helpers, or underscore
names. Replace direct `backend.app.app` deployment with `create_app()`.

## Staging checklist

Build from a lockfile, inspect the release artifacts, run the cross-browser
application, verify all auth providers, test proxy HTTPS/callback URLs, force a
stream timeout/disconnect, restart workers, test rollback, and retain the old
session key in `AUTH_SESSION_PREVIOUS_SECRET_KEYS` during rollout.
