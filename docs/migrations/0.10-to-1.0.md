# Migrate from Pytincture 0.10 to 1.0

The 1.0 line formalizes APIs and removes accidental dependency coupling. Use a
release candidate in staging before changing production.

## Installation extras

The base wheel no longer installs test tools, `pyodide-py`, Authlib, OneLogin,
Upstash, FastMCP, Argon2, or bcrypt. Install what the deployment enables:

```bash
pip install "pytincture[password,oauth,saml,redis,mcp]"
```

Contributors use `pip install ".[dev]"`. A startup/use error naming an extra
means the feature is enabled without its dependency group.

## Application factory and configuration

Prefer an importable ASGI application:

```python
from pytincture import PytinctureConfig, create_app

config = PytinctureConfig.from_env()
app = create_app(config)
```

Direct construction is isolated and does not read the environment.
`from_env()` applies explicit overrides, then environment values, then typed
defaults. Invalid modules paths, auth secrets/providers, Redis settings, CORS,
cookie policy, limits, replay-token sizes, proxy behavior, and log levels fail
at startup. `launch_service()` remains supported.

## Runtime behavior

- Packaged execution failures no longer silently fall back to inline code.
  Handle `PytinctureLifecycleError` and lifecycle events.
- `/healthz` and `/readyz` are the supported process/orchestration probes.
- Security logs are JSON and carry validated/generated request IDs.
- BFF calls and streams have time/byte limits and deterministic cleanup.
- Multiple workers need Redis for shared revocation and replay-token state.
- MCP is not mounted unless `ENABLE_MCP=true` and requires the `mcp` extra.

## Public versus internal APIs

Only names in [`contracts/public-api-v1.json`](../../contracts/public-api-v1.json)
or an explicit versioned contract are stable. Do not import registry globals,
route functions, middleware internals, generated-stub helpers, or underscore
names. Replace direct `backend.app.app` deployment with `create_app()`.

## Staging checklist

Build from a lockfile, inspect the release artifacts, run the cross-browser
application, verify all auth providers, test proxy HTTPS/callback URLs, force a
stream timeout/disconnect, restart workers, test rollback, and retain the old
session key in `AUTH_SESSION_PREVIOUS_SECRET_KEYS` during rollout.
